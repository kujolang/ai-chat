# Kujo maintenance transfer experiment — October 5, 2026

Freeze this protocol, specifications, seeds, positive controls, independent cases,
controller and exact Kujo binary before model generation. Six new synthetic Kujo
maintenance tasks cover configuration, pagination, ordered state transitions,
idempotent migration, atomic publication and lossless CSV export. These are small
specified tasks, not a senior-engineer certification or a large-repository trial.

Run baseline and feedback arms on GLM 5.3 Flash with the same Watchdog/Ollama profile,
existing compact/allocation/batch/always-review settings, one initial attempt per
task, 12000 response allowance and a 15-minute total per-task deadline. The feedback
arm adds runtime-qualified patterns. Grade its initial draft before showing any
counterexample; this measures patterns separately from subsequent repair. Apply
at most two five-minute repair requests within the SAME original deadline, only
when development checks fail. No retries of transport failures/uncertain execution.
A repair is explicit new authorized work on owned fixtures, never a request replay.

Development and holdout inputs are distinct and frozen. Only bounded development
counterexamples reach the model. Holdout results never inform repairs, model
selection, prompt changes or extra retries. Preserve pre-repair snapshots and
source hashes. The paired initial/final guided candidate is not another independent
round. Baseline receives the same independent measurements but no controller feedback.
Do not manually repair generated code. Preserve incomplete deliveries and their cost.

Calibrate positive controls and deliberately broken legacy seeds on the pinned
runtime before generation. Runtime-version-only labels are not binary qualification.
The controller must refuse unknown/unqualified binaries until the operator supplies
an exact qualified SHA. Checks execute real CLI entry points in fresh temporary
working directories with bounded output/time and verify disk outcomes where relevant.
Prompt restrictions and hashes are NOT a filesystem sandbox. Do not run untrusted
code or benchmarks against production state. Record observed out-of-scope reads.

Report delivery, development/holdout checks before and after, repair count, complete
versus incomplete usage, total reported tokens (INCLUDING repair), tool calls, elapsed
time and manual source quality separately. Grade compatibility, maintainability,
failure handling and test adequacy on anchored 0–4 scales: 0 missing/broken; 1 serious
defects; 2 material gaps; 3 appropriate and adequately verified; 4 exceptionally clear,
complete and proportionate. Scores are unblinded controller judgments, not objective
professional ranks. Compare source changes and quote specific evidence.

Promote no global default from one sample. A useful result requires fewer held-out
failures or concrete source-quality improvements, with no lost deliveries or new
contract failures, and explicit accounting of extra cost. If development passes
without repair, record that the repair loop was not exercised. New tasks are needed
to test generalization. Keep the runner provider-neutral so the exact frozen protocol
can later be repeated with an explicitly selected DeepSeek profile/model; do not
run DeepSeek or change its settings in this session.
